# AG-6 Policy sync and offline cache (apps/agent)

**Responsibility:** fetch all projects assigned to the enrolled employee (policy, destinations, canonical repos, fingerprints) via `GET /agent/projects`, cache them, apply ADR-004. Feeds AG-4 resolution (ADR-008). Also uploads newly learned repo fingerprints.
**Depends on:** AG-5, API-4.

## Contract
- `devguard sync` and implicit sync at push time (short timeout). Cache `{policy, version, fetchedAt}` per project. ETag/version to skip unchanged.
- `loadEffectivePolicy(project, now)` => `{policy, freshness: fresh|stale_ok|expired|missing}`; expired/missing => caller applies ADR-004 (enforce block / audit-only allow+record).
## Acceptance
Fresh, stale-within-TTL, beyond-TTL (enforce vs audit-only), missing cache, server version bump picked up, corrupted cache file => treated as missing.

## Implemented (apps/agent)
- **`devguard sync`** (`use-cases/sync-projects.ts`): `GET /v1/agent/projects` with the stored ETag (`config.json.projectsEtag`). On 200 every project is cached as `{fetchedAt, project, source: "server"}`, server-sourced projects that are no longer assigned are deleted, and the new ETag and `lastContactAt` are saved. On 304 only the fetch times are refreshed. The ETag is sent only when every cached policy file is readable (a damaged cache is rebuilt, not trusted). A reply with an unsafe or duplicate project id is refused as a whole. A failed sync (offline, revoked, 5xx) changes nothing. Exit 0 on success, 2 otherwise; `--json` supported. `enroll` runs a first sync (best effort).
- **Local vs server policies:** `CachedPolicy.source` is `server` or `local`/absent. `register --policy-file` writes `local`. Sync replaces a local policy for the same project with the server's, but never deletes or ages a local one (Gate 1 local mode is unchanged).
- **Freshness (ADR-004)** (`use-cases/policy-freshness.ts`): `classifyFreshness(fetchedAt, now, maxStaleMinutes)` => `fresh` (<= 5 min), `stale_ok` (<= limit), `expired` (older, unparsable, or from the future), `missing`. The limit is `DEVGUARD_POLICY_MAX_STALE_MINUTES` (default 60); anything that is not a positive whole number falls back to the default, never "off". This replaces the spec's `loadEffectivePolicy`: the repo resolver already returns the cached entry, so the runner classifies it.
- **At push time** (`run-pre-push.ts`): the hook first tries a sync with a 3 second timeout and no retries (best effort, `hookApi` in `main.ts`), so a slow server costs at most a few seconds and a failed refresh changes nothing. For each matched server policy: `expired` + enforce => block (rule `policy_unavailable`, even for an approved destination); expired + audit-only => allow and record (`wouldBlock: true`); an unknown mode counts as enforce. Any matched project may block (unchanged).
- **Fingerprint learning (ADR-008):** a repo recognised only by its remote (server project) reports up to 3 unknown root commits via `POST /v1/agent/repo-fingerprints` (best effort, from the hook), so later rewiring `origin` still resolves to the project.
- **Status:** each cached policy shows its source, fetch time and, for server policies, a note when stale or expired.
- **Tests:** freshness table, sync use case (stateful store; 304, removal, local-policy safety, unsafe ids, failures leave the cache untouched), runner freshness/refresh/learn cases, API client (`getProjects` ETag/304, contract validation, retries), CLI, store `deletePolicy`, plus a manual full-stack run (real API + Postgres + built CLI + real `git push` to bare remotes): enroll + first sync, approved push allowed, unapproved push blocked with the remote unchanged, fingerprint learned, rewired `origin` still blocked, policy change picked up at the next push, offline with a fresh cache still enforces, offline with an expired cache blocks an enforced project (even to an approved destination), back online recovers, unassignment drops protection.
- **Security review:** independent read-only review found no high issues. Fixed: fingerprint learning sent the raw push URL (a username can be a token), it now sends only the normalized `https://host/repo-path` and one root commit per project per push; the ETag is sent only while the cache holds exactly the projects it was built from (`config.json.syncedProjectIds`), so a deleted cache file is rebuilt instead of surviving a 304; `DEVGUARD_POLICY_MAX_STALE_MINUTES` is capped at 24 hours.
- **Known gaps:** an unreadable cache file is never cleaned up by sync (every push is blocked until `devguard status` is followed and the file removed: fail-safe but an availability cost); an edited server policy file stays edited until the server's policy changes (ADR-006: a local user can edit their own files); the 3 second hook refresh adds latency to every push when the server is slow; a local user can edit their own cache files (ADR-006); `--no-verify` bypasses everything (ADR-011); a cached policy with `source` removed is treated as local and never expires (the same user could simply uninstall the hook).
